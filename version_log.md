## [2.2.11]

### Security
- Enabled a strict content security policy for the app window (previously disabled), restricted the "open link" command to http(s) URLs only, and fixed a path-traversal edge case when unpacking `.brarchive` files.

### Fixed
- Fixed "Replace Unchanged" restoring assets in their original encrypted form that Minecraft could then no longer decrypt (showing purple/missing textures in-game — reported specifically on horses, skeletons, and creepers, whose containers happened to come back fully unchanged this patch version). The injected custom manifest.json's header/module `uuid` and `version` were always the custom template's own fixed placeholder values, not the pack's real Marketplace identity — Minecraft's DRM decryption checks the signed-in account's purchase entitlement against exactly those fields, so any content left in encrypted form silently stopped decrypting the moment the manifest was replaced. The injected manifest now preserves the real pack's own `uuid`/`version` (read from the Encrypted Dir) while keeping all the custom template's RTX-specific capabilities/subpacks/settings intact.
- Fixed patches built via Create Patch failing to apply with "target window checksum mismatch: XD3_INVALID_INPUT" on virtually any real Decrypted Dir, caused by two separate mismatches between how Create Patch built its `decrypted.vcdiff` reference source and how applying a patch actually normalizes a real pack: (1) a genuine pre-decrypted copy usually still has `contents.json`/`signatures.json`/`splashes.json`/`sounds.json`, which applying a patch always strips first but Create Patch wasn't stripping before baking its reference — fixed by excluding the same 4 files when building it, without touching the actual files in your Decrypted Dir; (2) the injected baseline `manifest.json` was being round-tripped through JSON serialization (reformatting to 2-space indentation) instead of copied byte-for-byte like the apply-side normalization does, silently changing its bytes even with identical content — this is now handled consistently by the same manifest-merging logic on both sides, so the two stay byte-identical.
- Fixed the Create Patch tool's "Extract Brarchives" option failing patch creation with a "Magic Mismatch" error when the Encrypted folder pointed at the actual Marketplace cache: it was trying to extract `.brarchive` containers there too, but those files are still genuinely DRM-encrypted at that point (already handled correctly elsewhere), so extraction could never succeed on them. It no longer tries. As a second layer of protection, any single unreadable `.brarchive` file anywhere is now skipped with a warning instead of failing the whole patch build.
- Fixed a data-loss bug introduced by that same "skip unreadable brarchive" fix: skipping a failed container avoided the crash, but the cleanup step right after still deleted every raw `__brarchive` folder unconditionally, regardless of whether its contents had actually been extracted. Any container that failed to read lost its content permanently — neither extracted nor kept in its original form. This is what broke Marketplace-mode patching specifically: the live Marketplace cache is always still DRM-encrypted, so effectively every container there "fails" to extract by design, and the pack being patched ended up missing most of its content (producing a corrupt, undersized package that then failed with "source file too short"). Unreadable containers are now left exactly where they are instead of being swept up by cleanup, so their original encrypted content survives.
- Fixed Marketplace-mode patching still failing afterward with "target window checksum mismatch" even with the above fix, if "Extract Brarchives" was enabled. The patch it applies (`encrypted.vcdiff`) is always built from the Marketplace cache zipped completely raw and untouched — but attempting extraction against the live cache, even when every real container correctly fails and is preserved, was still quietly deleting the handful of genuinely-empty placeholder archives as "safe to clean up." That's enough of a difference from the untouched reference to break xdelta3's byte-exact match. Extract Brarchives is no longer attempted at all in Marketplace mode (it can never succeed there anyway) — the live cache is now always used exactly as-is, matching how the patch was built.
- Fixed Marketplace auto-detect sometimes picking the wrong pack when another Oreville Studios product (e.g. a separate addon) was also installed — it could get confused between that pack and the real Actions & Stuff pack instead of reliably picking the right one.
- Turned off the Create Patch tool's "Replace Unchanged" option by default. It could ship patches where some assets stayed DRM-encrypted with no way for Minecraft to decrypt them, causing textures/models/sounds to silently fail to load. It's now clearly labeled as experimental if you re-enable it.
- Settings and diagnostics files (`settings.json`, `telemetry.json`) now save to your Windows user profile instead of next to the app, so they're no longer shared or overwritten between different installs.

### Added
- "Replace Unchanged" now also works at the whole-`.brarchive`-container level, not just individual loose files: if every asset that came out of a given container (e.g. `animation_controllers.brarchive`) is untouched by the RTX patch, the whole original encrypted container is restored as one file instead of shipping it as loose RTX-patched files. If even one entry inside a container changed, that entire container still ships patched — it can't be split apart once re-encrypted.
- Added a one-click, fully anonymous report for the known NVIDIA mob-texture-corruption issue (stretched/black/purple Zombie, Creeper, or Skeleton textures) — no Discord account needed, and it automatically attaches your hardware info, GPU driver events, and Minecraft content log, since diagnosing this specific bug needs all three.
- Added a full Wiki guide (`docs/WIKI.md`) covering every tab and tool, including when you actually need Extract Brarchives and how the Create Patch workflow works.
- Dependabot now actually watches for dependency updates across npm, Cargo, and GitHub Actions (its config was previously misconfigured and silently doing nothing).

## [2.2.10]

### Changed
- The finished pack now only installs into the shared Minecraft Bedrock profile (`Users\Shared\games\com.mojang\resource_packs`) instead of also copying into every other specific-user profile folder found on the machine — a pack placed in Shared already gets picked up regardless of which profile is signed in, so installing into each one individually was redundant. The remnant-cleanup scan is unaffected and still checks every profile folder, so leftovers from before this change (or from a previous version of the app) still get found and offered for cleanup.
- Hardware/RTX diagnostics (for users who opted in) are now checked fresh every time you open the Patcher instead of once per version — so changes like switching your BetterRTX preset show up sooner. We still only actually upload something if it's different from what we last sent, so nothing extra is sent on every launch.
- Diagnostics now include a one-way, anonymous hash derived from your PC so re-installing the Patcher doesn't create a second, duplicate hardware entry on our end. The original identifying value never leaves your machine, only its hash.

### Fixed
- Fixed the default folder suggested when picking your patched pack folder in the Patch Generator utility — it could point to the wrong location on some installs.
